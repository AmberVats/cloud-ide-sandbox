📌 1. Project Overview & Motivation

What we are building and what it accomplishes.

💡

What Are We Making?

CodeSphere is a full-featured browser-based Cloud IDE coupled with a high-throughput, multi-tenant remote code execution sandbox engine. It allows developers to write code across 6 programming languages, manage virtual multi-file workspaces, and receive real-time streaming output in a browser terminal without local compiler installations.

🎯

Core Problems Solved

Executing untrusted code on cloud servers invites severe security risks: infinite loops, memory leaks, fork bombs, and network scanning. CodeSphere eliminates these vulnerabilities using a dual-engine architecture with Linux kernel cgroups, --network none isolation, and 5-second process watchdog timers.

⚡

VS Code-Grade Editor

Microsoft Monaco Editor with IntelliSense, bracket colorization, font zooming, minimaps, and multi-file tabs.

📺

Real-Time Xterm Console

High-performance ANSI terminal streaming standard output and error chunks asynchronously with sub-25ms latency.

⌨️

Interactive Stdin

Live terminal keystrokes or pre-buffered test inputs feeding directly into input(), cin, and Scanner.

🚀 3. Phases of Project Development

How CodeSphere was conceptualized, built, and hardened.

Phase 1: Threat Modeling & Security Architecture
Analyzed hostile code vectors: infinite loops, memory leaks, fork bombs, and SSRF attacks. Defined hard resource constraints (256MB RAM, 0.5 CPU, 5s timeout) and zero-network egress boundaries.
Phase 2: Core Sandbox Engine & Process Isolation
Built the dual-engine execution layer: Dockerode cgroups runner with ephemeral volume mounts and Safe Process Runner with cross-platform termination (taskkill / SIGKILL).
Phase 3: WebSocket Streaming Protocol & REST API Gateway
Designed JSON-framed bi-directional streaming over /ws supporting RUN_CODE, STDOUT, STDERR, STDIN_INPUT, and EXECUTION_COMPLETE.
Phase 4: Cloud IDE Frontend (Monaco, Xterm.js & File Tree)
Implemented React 18 frontend with VS Code Monaco editor, Xterm.js interactive terminal, virtual file tree explorer, diagnostics telemetry badge, and language templates.
Phase 5: Containerization & Docker Compose Orchestration
Created production Alpine Dockerfiles for client and server, configured npm monorepo workspaces, and wrote multi-container docker-compose.yml with Redis integration.
Phase 6: Benchmarking & Edge-Case Hardening
Stress-tested infinite loops (verified 5s auto-kill), memory overflow bounds, unbuffered stdout streams, interactive stdin handling, and sub-25ms latency benchmarks.

docker-compose down

🛡️ 7. Security Analysis & Threat Mitigation

How hostile code execution is neutralized at every layer.

🛑

Infinite Loop Neutralization

Every execution is wrapped in a hard 5,000ms watchdog timer. When a script runs past 5 seconds, the server terminates the process with exit code 124 (TIMEOUT) using SIGKILL or Windows taskkill /f /t.

🔒

RAM & CPU Quota Throttling

Docker containers are constrained via Linux cgroups to a hard ceiling of 256MB RAM and 0.5 CPU core (500,000,000 NanoCpus). Memory overcommit triggers kernel OOM termination without impacting the host.

🚫

Zero Network Egress (--net none)

Containers are spawned with NetworkMode: 'none'. Malicious code cannot scan internal private subnets, connect to cloud metadata endpoints (SSRF), or launch external DDoS attacks.

🧹

Ephemeral Workspaces

Each execution runs inside an isolated temporary directory tagged with a UUID. After completion, the temporary directory is automatically purged, preventing filesystem pollution.
